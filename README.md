# J.A.R.V.I.S — גרסה משודרגת

JARVIS בנוי סביב שלושה עמודי תווך: (1) עוזר קולי שיחתי בסגנון ג'רוויס,
(2) **ניהול לו"ז ומיילים כשימוש המרכזי** — יומן פגישות, סדר יום, ותיבת דואר,
ו-(3) סוכן גמיש שמבצע כל בקשה/פקודה אחרת (פתיחת אפליקציות, חיפוש, ספוטיפיי,
כתיבת קוד ועוד — ראה את שני הסעיפים האחרונים). הסעיף "ניהול יומן ומיילים"
למטה הוא התוספת המרכזית של הגרסה הזו.

## ⚠️ קודם כל: המפתח שהיה בקוד
המפתח שהיה כתוב כברירת מחדל בקוד המקורי (`gsk_...`) נחשף לגמרי ברגע שהודבק כאן בצ'אט.
**תיכנס ל-https://console.groq.com/keys, תמחק אותו ותייצר מפתח חדש**, גם אם אתה לא מתכוון
להשתמש בגרסה הזו של הקוד. בקוד המשודרג אין יותר מפתח קבוע בתוך הקובץ בכלל — הוא חייב
להגיע ממשתנה סביבה, אחרת השרת פשוט מסרב לעלות עם הודעת שגיאה ברורה.

## התקנה

```bash
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux

pip install -r requirements.txt
```

תעתיק את `.env.example` לקובץ בשם `.env`, ותכניס לתוכו את המפתח החדש:
```
GROQ_API_KEY=gsk_your_new_key_here
```

הרצה:
```bash
python app.py
```
הדפדפן ייפתח לבד על `http://127.0.0.1:5000`.

## מה השתנה ולמה

### 1. אבטחה
- **הוסר המפתח הקבוע מהקוד** (הבעיה הכי דחופה — ראה למעלה).
- **`debug=True` + `host='0.0.0.0'`** — השילוב הזה חושף את דיבאגר ה-Werkzeug לכל הרשת;
  מי שמגיע לכתובת שלך יכול להריץ קוד פייתון על המחשב שלך. עכשיו השרת עולה על
  `127.0.0.1` (רק המחשב שלך) כברירת מחדל, ו-debug כבוי כברירת מחדל. אם באמת תרצה
  גישה מהטלפון באותה רשת, אפשר להגדיר `JARVIS_ALLOW_LAN=true` ב-`.env`, אבל דע שזה
  פותח את השרת לכל מי שבאותה רשת.
- **פתיחת אפליקציות דרך shell** — הקוד המקורי הריץ `subprocess.Popen(f"start {app_name}", shell=True)`,
  כלומר טקסט חופשי (כולל מה שתמלול קולי מזהה) עבר ישירות ל-cmd.exe. תו כמו `&` או `;`
  יכול לגרום להרצת פקודה נוספת. עכשיו אפליקציות מוכרות (chrome/spotify/notepad/וכו')
  נפתחות ישירות בלי shell, ואפליקציות לא מוכרות עוברות דרך `os.startfile`, שלא מפרש shell כלל.

### 2. "המוח" — הבנת פקודות
זו השדרוג המרכזי. הגרסה המקורית עבדה עם `if "weather" in text`, `if "open" in text`
וכו' — כל טעות הקלדה, ניסוח אחר, או אפילו מילה כמו "**closed**" (שמכילה "close") גרמה
להתנהגות לא צפויה. עכשיו ה-LLM עצמו מקבל **כלים אמיתיים** (tool calling / function calling):
`get_weather`, `open_application`, `close_application`, `web_search`, `play_media`. המודל
מחליט לבד איזה כלי מתאים ומה הפרמטרים, כך שניסוחים טבעיים ומגוונים הרבה יותר עובדים,
כולל כמה כלים באותה פקודה.

**שינוי מודל:** הקוד המקורי השתמש ב-`llama-3.3-70b-versatile`. גיליתי ש-Groq כבר הודיעו
על הפסקת התמיכה בו (17 ביוני 2026), עם כיבוי מתוכנן בעוד כשבועיים-שלושה. עברתי למודל
שהם ממליצים עליו כתחליף — `openai/gpt-oss-120b` — שתומך גם ב-tool calling. אם תרצה
תשובות מהירות/זולות יותר על חשבון קצת פחות "חוכמה", אפשר להחליף ל-`openai/gpt-oss-20b`
בשורה `MODEL_NAME` בתחילת `app.py`.

### 3. זיכרון שיחה
JARVIS עכשיו זוכר את השיחה הנוכחית (עד 12 חילופי דברים אחרונים), כך ששאלות המשך
כמו "ומה לגבי מחר?" עובדות. יש כפתור חדש **🧹 RESET** בממשק שמנקה את הזיכרון.
שימו לב: הזיכרון הוא גלובלי לתהליך (מתאים לעוזר אישי במחשב אחד), לא לפי משתמש.

### 4. אמינות
כל קריאה חיצונית (מזג אוויר, TTS, פתיחת/סגירת אפליקציות, pywhatkit) עטופה כך
שכשל אחד מחזיר תשובה מדוברת במקום לקרוס. ל-`play_media` יש גם נפילה-לאחור: אם
pywhatkit נכשל (הוא ידוע כלא כל כך יציב), נפתחות תוצאות חיפוש ביוטיוב במקום
להיכשל בשקט.

### 5. ממשק (עיצוב לא נגעתי בו!)
- מצב חדש **PROCESSING** (עיגול זהב פועם) בזמן שה-HUD מחכה לתשובה מהשרת — קודם
  זה פשוט נשאר על "LISTENING..." בלי לתת פידבק שהמערכת עובדת.
- תוקן מרוץ תנאים (race condition) בהפעלה מחדש של זיהוי הדיבור, שיכול היה
  לגרום לשגיאות שקטות בקונסול כשכמה קריאות ל-`recognition.start()` התנגשו.
- הודעה ברורה בלוג אם הדפדפן חוסם גישה למיקרופון, במקום שקט מוחלט.

## הרחבה חדשה: Spotify, פיינט ומחשבון

שלושה כלים חדשים נוספו ל-LLM (`play_on_spotify`, `draw_shape_in_paint`, `calculate`).
תוקן גם באג קטן: `index.html` היה בשורש התיקייה במקום בתוך `templates/`, מה שהיה
גורם ל-`render_template` להיכשל עם `TemplateNotFound` — עכשיו הוא במקום הנכון.

### Spotify — ניגון שיר אמיתי
בעבר `open_application("spotify")` רק פתח את האפליקציה. עכשיו `play_on_spotify`
באמת מחפש ומנגן שיר ספציפי, דרך ה-Web API הרשמי של Spotify (לא קליקים מדומים):

1. תיכנס ל-https://developer.spotify.com/dashboard ותצור אפליקציה (Create app).
2. ב-Redirect URI תוסיף **בדיוק**: `http://127.0.0.1:8888/callback`
3. תעתיק את ה-Client ID וה-Client Secret ל-`.env`:
   ```
   SPOTIFY_CLIENT_ID=...
   SPOTIFY_CLIENT_SECRET=...
   ```
4. תריץ פעם אחת `python spotify_login.py` — פותח דפדפן להתחברות, ושומר טוקן
   ב-`.spotify_cache` כדי שלא תצטרך להתחבר שוב בכל הפעלה. (אם תדלג על זה,
   ההתחברות תקרה ממילא בפעם הראשונה שתבקש שיר, רק שזה יקרה תוך כדי פקודה
   קולית — עלול להיראות כאילו המערכת נתקעה.)

**מגבלה של Spotify עצמו (לא של הקוד):** שליטה בניגון (`start_playback`) דורשת
**חשבון Premium**, וגם **מכשיר פעיל** (האפליקציה פתוחה איפשהו — מחשב/טלפון/
דפדפן). אם אין מכשיר פעיל, הקוד מנסה לפתוח את אפליקציית הדסקטופ אוטומטית
ולחכות כמה שניות; אם זה עדיין לא עוזר, תפתח את Spotify ידנית פעם אחת ונסה שוב.

### פיינט — ציור צורה אמיתי
`draw_shape_in_paint` פותח את Paint, ממקסם את החלון, לוחץ על כלי האליפסה
ב-ribbon, וגורר את העכבר תוך החזקת Shift (כדי לקבל עיגול מושלם).

**חשוב להבין את המגבלה כאן:** בניגוד ל-Spotify (API רשמי) ולמחשבון (קלט
מקלדה), אין API רשמי לשלוט ב-Paint — זה מבוסס על **קליק בקואורדינטות
פיקסלים**. הקואורדינטות בראש `app.py` (`PAINT_ELLIPSE_TOOL_REL` ו-
`PAINT_CANVAS_START_REL`) הן ניחוש התחלתי בלבד ו**כנראה ידרשו כיול** אצלך —
תלוי בגרסת Windows/Paint ובקנה המידה (DPI) של המסך. הרצה של:
```bash
python calibrate_paint.py
```
מציגה בזמן אמת את מיקום העכבר (בפיקסלים ובשבר 0-1) — תעבור עם העכבר על כלי
האליפסה ואז על הקנבס, ותעדכן את הערכים המתאימים ב-`app.py`. כרגע נתמך רק
עיגול; אפשר להרחיב לצורות נוספות באותה שיטה (עוד קואורדינטה מכוילת לכל צורה).

### מחשבון — חישוב אמיתי ומוצג על המסך
`calculate` עושה שני דברים: (1) מחשב את התוצאה **בעצמו**, בבטחה — לא עם
`eval()` על טקסט חופשי, אלא עם פענוח עץ-תחביר (AST) שמאפשר רק מספרים
ואופרטורים חשבוניים, כך שגם אם המודל "יזריק" משהו לא צפוי זה לא יכול להריץ
קוד; (2) מקליד את הביטוי בפועל לתוך אפליקציית המחשבון ולוחץ Enter, כך שזה גם
נראה על המסך. בניגוד לפיינט, זה **לא** תלוי בקואורדינטות — מחשבון Windows
תומך בקלט מקלדה מלא, אז זו ההרחבה הכי אמינה מבין השלוש.

## ניהול יומן ומיילים (Google + Microsoft)

זה השימוש המרכזי של הגרסה הזו: JARVIS מתחבר ליומן ולתיבת הדואר שלך —
Google (Calendar + Gmail) ו/או Microsoft (Outlook/365 דרך Graph API), אפשר
להגדיר אחד מהשניים או את שניהם במקביל. אם שניהם מוגדרים, תוצאות היומן
והמיילים מוצגות ממוזגות משני המקורות יחד.

**רמת האוטונומיה — קריאה חופשית, כתיבה רק באישור:** JARVIS יכול לקרוא
יומן ומיילים בכל שיחה בלי לבקש רשות (`get_daily_agenda`, `get_calendar_events`,
`list_emails`). אבל **הוא לעולם לא יוצר אירוע ביומן או שולח מייל בפועל
מיוזמתו** — `create_calendar_event` ו-`send_email` רק רושמים בקשת אישור
(אותו מנגנון confirm-to-act שכבר קיים ב-`guardrails.py` למחיקת קבצים
וסגירת תהליכים), ואתה מאשר או מבטל בקול/בטקסט ("כן"/"לא", "yes"/"no").
עד שלא אישרת בפירוש — שום דבר לא נוצר ולא נשלח.

### הגדרת Google
1. https://console.cloud.google.com/ → פרויקט חדש → תפעיל את **Calendar
   API** ו-**Gmail API**.
2. Credentials → Create Credentials → OAuth client ID → סוג **Desktop app**.
3. תעתיק את ה-Client ID וה-Client Secret ל-`.env`:
   ```
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...
   ```
4. תריץ פעם אחת `python google_login.py` — פותח דפדפן להתחברות ואישור
   הרשאות, ושומר טוקן ב-`.google_cache/token.json` כדי שלא תצטרך להתחבר
   שוב (ומתחדש אוטומטית ברקע).

### הגדרת Microsoft (Outlook/365)
1. https://portal.azure.com/ → Azure Active Directory → App registrations
   → New registration.
2. Authentication → Add a platform → **Mobile and desktop applications** →
   תסמן `http://localhost` כ-redirect URI, ותפעיל **Allow public client
   flows**.
3. API permissions → Microsoft Graph → Delegated permissions:
   `Calendars.ReadWrite`, `Mail.Read`, `Mail.Send`, `User.Read`.
4. תעתיק את ה-Application (client) ID ל-`.env`:
   ```
   MS_CLIENT_ID=...
   MS_TENANT_ID=common
   ```
   (`common` תומך גם בחשבונות אישיים וגם בחשבונות ארגוניים; אפשר להחליף
   ל-tenant ID ספציפי כדי להגביל לארגון אחד.)
5. תריץ פעם אחת `python microsoft_login.py` — אותו רעיון כמו Google, שומר
   טוקן ב-`.ms_cache.bin`.

### לו"ז יומי — גם לפי דרישה, גם באופן יזום
- **לפי דרישה:** תשאל בכל רגע "מה הלו"ז שלי היום?" / "יש לי מיילים חדשים?"
  והמודל יקרא ל-`get_daily_agenda` / `get_calendar_events` / `list_emails`.
- **יזום:** פעם ביום, בשעה `JARVIS_BRIEFING_HOUR:JARVIS_BRIEFING_MINUTE`
  (ברירת מחדל 08:00), JARVIS בונה תקציר יום ומדבר אותו מעצמו — גם בלי
  שהתעוררת אותו. אפשר לכבות עם `JARVIS_DAILY_BRIEFING=false`.
- **חשוב לאמינות:** התקציר היזום **לא** קורא ל-Groq בכלל — הוא בנוי
  ישירות מנתוני היומן/מייל בפורמט טקסט (`productivity_service.py`),
  בכוונה, כדי שלא ייפול אם מפתח ה-API פג תוקף/נגמרה המכסה. אם ה-LLM לא
  זמין, שאילתות "לפי דרישה" ייכשלו בעדינות (הודעה מדוברת), אבל התקציר
  היומי היזום ימשיך לעבוד תמיד.

### אם ההתחברות נכשלת עם שגיאת SSL (`CERTIFICATE_VERIFY_FAILED`)
זה קורה כשתוכנת אנטי-וירוס/פרוקסי במחשב עושה בדיקת TLS משלה עם תעודת
root שוויינדוס כבר סומך עליה, אבל חבילת `certifi` המובנית של פייתון לא.
[cert_bootstrap.py](cert_bootstrap.py) פותר את זה **רק בתוך התהליך של
JARVIS** (לא נוגע בשום דבר גלובלי במחשב) — הוא בונה קובץ אישורים משולב
תחת `.certs/` (certifi + תעודות ה-root שכבר מותקנות ב-Windows) ומצביע
אליו. אם זה עדיין נכשל, תריץ פעם אחת (PowerShell, לא כחלק מהקוד):
```powershell
$certs = (Get-ChildItem Cert:\LocalMachine\Root) + (Get-ChildItem Cert:\CurrentUser\Root)
$out = ".certs\combined_ca_bundle.pem"
Get-Content (python -c "import certifi;print(certifi.where())") | Set-Content $out
foreach ($c in $certs) {
    "-----BEGIN CERTIFICATE-----" | Add-Content $out
    [Convert]::ToBase64String($c.RawData,'InsertLineBreaks') | Add-Content $out
    "-----END CERTIFICATE-----" | Add-Content $out
}
```

### מגבלות
- אם שני הספקים מוגדרים ו-`create_calendar_event`/`send_email` לא מציינים
  ספק, ברירת המחדל היא Google; אפשר להכריח ספק ספציפי דרך פרמטר `provider`
  ("google" / "microsoft") — או פשוט לומר "ביומן של Outlook" וכו', והמודל
  יעביר את זה בפרמטר.
- אין עדיין תמיכה בעריכת/מחיקת אירועים קיימים, רק יצירה — וגם זו רק בבקשת
  אישור.
- ה-SSE feed (`/api/stream`) שמעביר את בקשות האישור ואת התקציר היזום
  להאזנה בממשק היה קיים כבר קודם בצד השרת (`event_stream.py`) אבל לא היה
  מחובר לצד ה-HTML בכלל — עכשיו יש `EventSource` שמאזין לו מרגע טעינת הדף.

## גישה מהטלפון (LAN) ולוקאלית מול חבילה מותקנת

ברירת המחדל היא ש-JARVIS מאזין רק על `127.0.0.1` (המחשב הזה בלבד). כדי לגשת
מהטלפון (או ממחשב אחר) **באותה רשת**:

1. הגדר `JARVIS_ALLOW_LAN=true` ב-`.env` ותפעיל מחדש את `app.py`/ה-exe.
2. תברר את כתובת ה-IP המקומית של המחשב (PowerShell: `ipconfig`, שורת
   IPv4), למשל `192.168.1.50`.
3. בדפדפן בטלפון (**באותה רשת Wi-Fi**): `http://192.168.1.50:5000`.
4. ודא שחומת האש של Windows לא חוסמת את הפורט (בפעם הראשונה Windows בדרך
   כלל שואל "Allow this app through the firewall?" — תאשר לרשתות פרטיות).

**שתי מגבלות אמיתיות שגילינו בבדיקה — לא באגים בקוד, אלא התנהגות דפדפן/Google
שאי אפשר לעקוף בלי תשתית נוספת (HTTPS אמיתי / דומיין):**

- **קול לא יעבוד דרך IP רגיל, רק טקסט.** דפדפנים (Chrome/Safari/Edge כולם)
  חוסמים `getUserMedia`/`SpeechRecognition` (המיקרופון) על כל עמוד שאינו
  "secure context" — כלומר HTTPS, או `http://localhost`/`127.0.0.1`
  ספציפית. `http://192.168.1.50:5000` **אינו** נחשב secure context, אז
  בטלפון תמיד תיפול לקלט טקסט בלבד (המערכת מזהה את זה אוטומטית ומציגה
  הודעה ברורה + כפתור "CONTINUE WITH TEXT INPUT", לא נתקעת בלי הסבר).
  כדי שגם קול יעבוד מהטלפון צריך HTTPS אמיתי — הכי פשוט: טאנל כמו
  `cloudflared tunnel --url http://127.0.0.1:5000` או `ngrok http 5000`,
  שנותן כתובת `https://...` חיצונית שמצביעה למחשב שלך.
- **חיבור Google לראשונה חייב לקרות מהדפדפן של המחשב (`127.0.0.1`), לא
  מהטלפון.** ה-OAuth client מסוג "Desktop app" מקבל מגוגל פטור אוטומטי
  (loopback exemption) רק ל-`127.0.0.1`/`localhost` — לא לכתובת IP ברשת
  המקומית. אם תנסה ללחוץ "CONNECT GOOGLE ACCOUNT" מהטלפון לפני שחיברת
  פעם אחת מהמחשב, גוגל יסרב לבקשה. **סדר נכון:** תחבר את Google פעם אחת
  מהדפדפן במחשב (`http://127.0.0.1:5000`) — הטוקן נשמר בצד השרת
  (`.google_cache/token.json`) ומשותף לכל מכשיר שמתחבר אחר כך, כולל
  הטלפון, בלי לחבר שוב.

זו גם הסיבה ש-Werkzeug (שרת הפיתוח המובנה של Flask) מספיק בפועל כאן: אין
דומיין, אין תעודת TLS אמיתית — זה שרת LAN אישי, לא שירות פומבי.

## אריזה כאפליקציית Windows (PyInstaller)

יש עכשיו קובץ build מוכן ב-[packaging/jarvis.spec](packaging/jarvis.spec)
שהופך את `app.py` (ועוד שלושה סקריפטי login חד-פעמיים) לקובצי `.exe`
עצמאיים — לא צריך שהמחשב של הלקוח יתקין Python בכלל. פירוט מלא, כולל למה
כל החלטה (onefile, console=True, מה כן/לא נכלל) ב-
[packaging/BUILD.md](packaging/BUILD.md). בקצרה:

```powershell
pip install pyinstaller
pyinstaller packaging\jarvis.spec --distpath dist --workpath build --clean
```

התוצאה ב-`dist\JARVIS.exe` וכו' — זה **נבדק בפועל** בסבב העבודה הזה (ראה
BUILD.md): הקובץ רץ, טוען את הטמפלט, מדבר עם edge-tts, ומציג את הודעת
השגיאה הנקייה שלו אם `GROQ_API_KEY` חסר, בלי traceback מפחיד.

## מגבלות ידועות (לא שיניתי, רק שקוף)
- **pywhatkit** ידוע כלא אמין (הוא בפועל פותח דפדפן ומדמה הקלדה), ולכן יש עכשיו נפילה-לאחור.

- זיהוי דיבור בדפדפן (Web Speech API) עובד הכי טוב ב-Chrome/Edge שולחניים.
  **ב-iOS Safari (וב-WebView-ים מבוססי iOS כמו Chrome-on-iOS) אין תמיכה
  ב-Web Speech API בכלל** — זו מגבלת אפל, לא של הקוד. המערכת מזהה את זה
  אוטומטית ועוברת למצב קלט-טקסט-בלבד עם הודעה ברורה במקום להיתקע בשקט
  (זה תוקן בסבב הזה — קודם המודל היה נשאר תקוע מאחורי המסך של "SAY WAKE
  UP" בלי שום דרך לצאת ממנו בדפדפן כזה).
- אם תרצה שהאינטראקציה (זיהוי דיבור + תשובות) תהיה בעברית, צריך לשנות גם את
  `recognition.lang` בקובץ ה-HTML וגם את ה-`SYSTEM_PROMPT` וקול ה-TTS ב-`app.py`.
- **ציור בפיינט** מבוסס על קואורדינטות פיקסלים (אין API רשמי ל-Paint) —
  כמעט בוודאות ידרוש כיול עם `calibrate_paint.py` אצלך, ותומך כרגע רק בעיגול.
- **שליטה ב-Spotify** (`start_playback`) דורשת חשבון Premium ומכשיר Spotify
  פעיל (אפליקציה פתוחה במחשב/טלפון/דפדפן) — מגבלה של Spotify עצמו, לא של הקוד.

  לא בפונקציות כמו שורש או סינוס.
